# TraeWorkCheckin 🎯

> 🚀 **TraeWork / Trae CN 桌面端全自动每日签到与积分管理工具**  
> 具备**开机登录无感自启**、**网络异步自愈探测**、**已签到智能跳过（严格防风控）**、**屏幕右下角原生系统通知**、**零后台内存驻留**与**极简交互控制台**等特性。  
> 纯标准原生库实现，**零第三方依赖**，已深度优化兼容 Windows 10/11、macOS 与 Linux。

---

## 📖 项目背景与研发初衷

在字节跳动 Trae 的积分与激励体系下，每日签到可领取 **200 积分**（基础 150 积分 + 额外 50 积分，月累计达 6,000+ 积分，可用于兑换高级模型调用额度与专属功能）。但在日常高频开发与忙碌工作中，开发者极易忘记每天手动打开客户端点击签到，白白错失积分。

市面上早期社区脚本普遍存在以下硬伤：
1. **传统定时任务易漏签**：原方案通常绑定在每天上午固定时间执行。若此时电脑处于关机或休眠状态，将导致当天直接漏签；
2. **开机直接启动易断网报错**：若直接挂在开机运行，由于开机时系统网卡与 Wi-Fi 往往尚未连接就绪，脚本启动即报 DNS 解析失败或网络不可达中断退出；
3. **缺乏防风控与盲目发起请求**：不论是否已签，盲目向签到接口发送 POST 请求，容易触发服务端反爬与高频限流判定；
4. **官方安全校验与伪装限流**：缺少设备指纹校验报错 `Code: 9004`，请求体缺少 `req_source` 或传错设备 ID 触发服务端风控伪装报错 `Code: 9074`（当前参与用户太多，请稍后再试）；
5. **任务名泛化引发冲突**：缺乏统一命名空间规范，容易与系统内其他自动签到工具（如 WorkBuddyCheckin）发生任务覆盖或误删冲突；
6. **缺乏反馈与黑框打扰**：后台静默执行缺乏视觉反馈，Token 失效用户无法感知。

**TraeWorkCheckin** 针对上述问题进行了彻底重构与全面工程化优化，打造出真正**最安全、效率最高、资源最优、兜底保障、最方便用户**的全自动签到解决方案。

## 🌟 核心功能特性（五大设计原则）

### 1. 🛡️ 最安全（Zero Wind Control Risk）
- **先查后签**：启动后优先查询签到状态，若 `checked_in` 为真，**秒级自动跳过，坚决不向签到接口发 POST 请求**，彻底杜绝被服务器风控标记为高频刷接口；
- **防时间指纹与抖动（Jitter）**：开机自启静默模式下自动加入 2~5 秒随机浮动延时，重试时加入 12~26 秒指数退避，杜绝机械化并发特征；
- **官方协议与设备指纹 100% 拟真**：自动提取字节跳动官方设备中心注册的真实 16 位数字 DID（`x-device-id`），识别客户端类型注入 `req_source: 2/1`，并装配标准请求头（`Authorization: Cloud-IDE-JWT <token>`、`x-device-type`、`x-os-version`、`X-Machine-Id`、`X-User-Id`、`X-User-Region`、标准 `User-Agent` 与 `Content-Type: application/json`），彻底根治 9074 伪装限流拦截；
- **纯本地只读与隐私保护**：对客户端配置文件采取只读访问，日志仅打印脱敏 UID 与 DID（如 `1599****41`），绝不上报或外泄明文 Token。

### 2. ⚡ 效率最高（High Efficiency）
- **开机网络异步就绪与自愈探测**：解决开机时网卡、Wi-Fi 尚未联网的问题。脚本启动后以底层 TCP Socket 轻量探活国内核心网络节点。若尚未联网，**自动进入低开销等待队列（每 5 秒探测一次，最长 300 秒）**，一旦网络连通瞬间自动恢复执行，杜绝开机断网漏签；
- **秒级执行平稳退出**：已签到状态下全流程耗时 1~2 秒，毫秒级网络 I/O 响应。

### 3. 🍃 资源最优（Zero Memory Footprint）
- **纯标准内置库实现**：零第三方 npm 扩展包依赖，无论是系统 Node 18+ 还是 Trae 内置运行时，开箱即用；
- **零内存常驻**：无论是签到成功、还是检测到今日已签跳过，在完成日志追加与桌面通知后，**立即调用 `process.exit(0)` 退出进程**，进程即刻销毁，**零后台常驻进程，内存占用彻底归零**。

### 4. 🎯 兜底保障（Daily Guarantee - 三重保障机制）
- **第一道防线（运行时随机退避重试）**：遇到网络闪断或服务端 9074 限流，内置最大 8 次指数退避抖动重试；
- **第二道防线（单次计划任务兜底与自愈注销）**：若因长期断网超时等极端情况导致开机未成功签到，脚本自动在 Windows 中注册一个 30 分钟后的单次重试任务（**任务名规范为 `TraeWorkCheckin_Retry`**）；任何一次成功执行后自动自愈注销该任务，不留系统垃圾；
- **第三道防线（登录态失效告警）**：遇凭证过期或 401 鉴权失效时，系统弹窗明确提示用户打开客户端刷新登录。

### 5. 💻 最方便用户（Ultimate User Experience）
- **极简交互式管理控制台**：双击 `manage_autostart.cmd` 即可使用纯中文界面，支持键盘 `[↑ / ↓]` 箭头与数字键切换；
- **屏幕右下角原生通知**：运行完毕后，**屏幕右下角自动弹出系统原生 Toast / 托盘气泡通知**（展示今日状态、累计积分明细），无需手动翻查日志；
- **任务名强隔离（防冲突保障）**：启动任务与计划任务名称强绑定 **`TraeWork`** 字样（如 `TraeWorkCheckin.lnk`、`TraeWorkCheckin_Retry`），与 WorkBuddyCheckin 等其他任务完全独立，绝不冲突。

## 🚀 快速上手指南

### 🪟 Windows 系统使用（推荐）

#### 1. 配置开机自启（只需操作一次）
直接双击运行 **`manage_autostart.cmd`**（或在 PowerShell 中运行 `manage_autostart.ps1`）：
- 弹出纯中文交互式控制台菜单，**支持键盘 `[↑ / ↓]` 方向键移动光标，按 `[Enter]` 确认选择**（亦可直接按下数字快捷键）：
  - **`[1] 安装开机自启任务`**：一键在 Windows 启动项目录生成后台静默任务（`TraeWorkCheckin.lnk`），开机自动检测签到并在右下角弹窗通知；
  - **`[2] 卸载开机自启任务`**：一键彻底移除已配置的快捷方式与所有 `TraeWork*` 临时兜底计划；
  - **`[3] 立即测试执行签到`**：即刻运行一次并输出详细播报；
  - **`[0] 退出管理程序`**。

#### 2. 手动单次测试运行
- 直接双击 **`run_traework_checkin.cmd`**（或快捷入口 **`run_checkin.cmd`**）即可执行，执行完毕窗口自动保留（带有 `pause`），方便查看输出。

---

### 🍏 macOS / 🐧 Linux 系统使用

#### 1. 配置登录自动签到
进入项目目录后执行自启管理脚本：
```bash
chmod +x manage_autostart.sh run_checkin.sh
./manage_autostart.sh
```
- 输入对应数字确认操作：
  - **选项 `1`**：macOS 自动创建 `com.traework.checkin` LaunchAgent 服务，Linux 自动创建 `traework_checkin.desktop` 桌面自启条目；
  - **选项 `2`**：彻底卸载清理；
  - **选项 `3`**：立即测试执行。

#### 2. 手动单次运行
```bash
./run_checkin.sh
# 或直接通过 Node.js 运行：
node checkin.js
```

## 🔒 安全性与隐私说明

- **100% 纯本地运行**：只读取本机官方客户端已落盘的临时凭据，本地 WebCrypto 硬件加速解密，不依赖任何第三方远程服务器；
- **绝不上传或泄露敏感凭证**：日志与控制台仅打印脱敏的 UID（如 `1599****41`），绝不打印或保存完整的 JWT Token；
- **只读模式保护**：对客户端 `storage.json` 采取严格的**只读**操作，绝不修改客户端本地任何数据；
- **严格风控防御**：今日已签坚决不发 POST 签到请求，开机加入随机浮动延时，杜绝机械化机器特征。

## ❓ 常见问题 (FAQ)

**Q: 提示「未检测到任何有效的 Trae 登录凭据」？**  
A: 请先启动并登录一次 Trae / TraeWork 桌面端客户端（登录后系统会自动落盘凭据文件）。

**Q: 提示「登录凭据 token 已失效」？**  
A: 说明本地登录态已过期，只需重新打开 Trae 客户端刷新登录即可自动同步。

**Q: 每天开机会不会重复签到或多扣积分？**  
A: 绝不会。脚本具备状态前置检测，今日已签到时直接跳过，零网络冗余且服务端天然具备幂等性。

**Q: 屏幕右下角通知没有弹出来？**  
A: 请确认 Windows 系统设置中是否开启了“专注助手（免打扰模式）”或关闭了通知权限。通知即便未弹出，签到结果也已准确记录在 `log/checkin.log` 中。

**Q: 为什么之前脚本总报「Code: 9074 当前参与用户太多，请稍后再试」，但界面点一下却能成功？**  
A: `9074` 实际上是字节跳动服务端在遇到请求体缺少 `req_source` 或使用了无效设备指纹时的**风控拦截伪装话术**。本项目已全面修复该问题：自动识别当前客户端类型并注入对应 `req_source: 2/1`，同时从本地存储中提取真实的字节跳动 16 位数字 DID（`x-device-id`），彻底消除 9074 伪装限流。

**Q: 与其他自动签到脚本（如 WorkBuddyCheckin）一起用会冲突吗？**  
A: 完全不会。本项目所有开机启动项、任务计划程序与重试任务均强制带有 `TraeWork` 命名空间前缀（如 `TraeWorkCheckin`、`TraeWorkCheckin_Retry`），两者完全独立互不影响。
